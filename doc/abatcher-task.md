# АВМ-Пакетник — контекст задачи

> Файл-памятка для продолжения работы над подпроектом. Не удалять, обновлять по ходу реализации.

## Что это

Новый подпроект наряду с АВМ-Сервис (`coma`) и АВМ-Наладкой — **АВМ-Пакетник**.
Каталоги: `src/abatcher` (Qt-приложение, класс `Abatcher` — главное окно) и `src/avm-autobatch` (упаковка/сборка, `avm-autobatcher.rc`, `package/src/avm-autobatcher.tsv`).

Назначение: автоматизированное выполнение последовательности задач на подключённом по USB модуле — считать текущее состояние (BSI/конфиг/журналы), при необходимости обновить ВПО и конфигурацию до эталонных значений, проверить результат, упаковать все скачанные файлы в ZIP.

Работа идёт в двух режимах: обычный и **"Пробный запуск"** (чекбокс `m_isDry` / `isDry`, уже есть в UI). В пробном режиме шаги, которые могут менять состояние устройства (заливка ВПО, отправка конфигурации) или проверять результат такого изменения, **не выполняются взаправду** — вместо этого пишется предупреждение в лог, а соответствующие пункты 10-12 и 14-16 (см. список ниже) считаются пройденными успешно.

## Полный список шагов пакетника

1. Диалог выбора USB-устройства + галочка "Пробный запуск". **Реализовано** — `Abatcher::createUSBConnectionsWindow`/`updateUSBConnectionWindow` в [abatcher.cpp](../src/abatcher/src/abatcher.cpp), галочка в `createDryCheckBox`.
2. Подключение к устройству по USB. **Реализовано** — `ModuleWorker::connectToUSB` в [moduleWorker.cpp](../src/abatcher/src/moduleWorker/moduleWorker.cpp), плюс аналог в АВМ-Сервис: `ConnectDialog` / `Coma::initConnection` ([coma.h:50](../src/coma/include/coma.h#L50)).
3. Скачать блок Bsi → сохранить `bsi-old`. **Реализовано** — `ModuleWorker::saveBsi` в [moduleWorker.cpp](../src/abatcher/src/moduleWorker/moduleWorker.cpp).
4. Скачать блок BsiExt (если есть) → сохранить `bsiext`. **Реализовано** — `ModuleWorker::saveBsiExt` (проверяет `HaveBSIExt()`, при отсутствии блока шаг считается пройденным).
5. Скачать конфигурацию → сохранить `config-old`. **Реализовано** — `ModuleWorker::requestConfig`/`saveConfig`.
6. Скачать журналы → сохранить `sysjour`, `workjour`, `measjour`. **Реализовано** — `ModuleWorker::saveJournals`/`saveJournal` (sysjour качается всегда, workjour/measjour — если есть по `HaveWorkJournal()`/`HaveMeasJournal()`).
   - Пункты 3-6 реализованы в `ModuleWorker` напрямую (через `SyncConnection`/`S2DataManager`/`FileProvider`), по образцу `Engines::Slices` — [slices.h](../src/coma/include/engines/slices.h) / [slices.cpp](../src/coma/src/engines/slices.cpp). Файлы пока складываются во временную папку (`QTemporaryDir m_tempDir`), упаковка в ZIP и диалог сохранения — ещё не сделаны, см. пункт 17. Образец архивирования: `Slices::createSlice()` ([slices.cpp:21](../src/coma/src/engines/slices.cpp#L21)) + `ZipUtil::CompressDir` ([slices.cpp:48](../src/coma/src/engines/slices.cpp#L48)).
7. Скачать настроечные блоки (Bac) → сохранить `bac1`, `bac2`, …
8. Скачать блоки начальных значений → сохранить `startup`.
   - Пункты 7-8: **не реализовано**. Информация о том, какие Bac/Startup блоки есть у модуля, в XML пока не описана — придётся хардкодить список блоков в зависимости от типа модуля (тип берётся из Bsi).
9. Анализ версии ВПО — сравнение с актуальной версией для данного модуля.
10. При несовпадении — принудительная отправка ВПО и переход на новое (с рестартом связи). В "Пробном запуске" — только предупреждение + запись в лог.
11. Скачать блок Bsi → сохранить `bsi`, сравнить версии ВПО. **В "Пробном запуске" пункт полностью пропускается.**
12. При несовпадении — ERROR в лог; при совпадении — INFO: `"Обновление ВПО с версии <old> на версию <new> проведено успешно"`. **В "Пробном запуске" пропускается.**
    - Пункты 9-12 (обновление ВПО): см. существующий `FwUploadDialog` — [fwuploaddialog.h](../src/coma/include/dialogs/fwuploaddialog.h) / [fwuploaddialog.cpp](../src/coma/src/dialogs/fwuploaddialog.cpp) в АВМ-Сервис, использовать как основу.
13. Анализ значений заданных по ID конфигурационных параметров со значениями в модуле.
14. Принудительная установка параметров и отправка конфигурации в модуль. В "Пробном запуске" — только предупреждение + лог.
15. Скачать конфигурацию → сохранить `config`, проверить заданные параметры. В "Пробном запуске" — пропускается.
16. При несовпадении хотя бы одного параметра — ERROR в лог; при полном совпадении — INFO: `"Обновление конфигурации проведено успешно"`. В "Пробном запуске" — пропускается.
17. Упаковка всех сохранённых файлов в один ZIP, диалог сохранения архива, итоговое сообщение об успехе/неуспехе всей работы. **Реализовано** (пока только упаковка+диалог+сообщение об успехе/ошибке для того, что скачано на шагах 1-6 — пункты 7-16 ещё не собирают файлы для архива). По клику "Начать скачивание" сразу открывается `FileFunc::chooseFileForSave` (см. `ModuleWorker::startDownload`), путь сохраняется в `m_zipFileName`; по завершении конвейера `ModuleWorker::finishDownload` архивирует `m_tempDir` в этот файл через `ZipUtil::CompressDir` и показывает итоговое сообщение. Флаг `m_isCancelled` используется не только для отмены пользователем, но и как индикатор "что-то пошло не так" (по аналогии с `Slices`) — выставляется во всех точках ошибки скачивания/сохранения отдельных файлов, чтобы не показать ложное "Архив сохранён" после сбоя.
    - Образец упаковки: `Slices::createSlice()` + `ZipUtil::CompressDir` (см. пункт 3-6 выше).
    - **В "Пробном запуске" пункты 10-12 и 14-16 считаются пройденными успешно** (несмотря на то что реально не выполнялись).

## Текущее состояние кода (на момент записи, 2026-07-02)

- `Abatcher` ([abatcher.h](../src/abatcher/include/abatcher.h)/[.cpp](../src/abatcher/src/abatcher.cpp)) — главное окно: таблица USB-устройств с автообновлением по таймеру (3 сек), чекбокс "Пробный запуск", кнопка "Запуск". По клику создаётся `ModuleWorker`, окно переключается на него через `QStackedWidget`.
- `ModuleWorker` ([moduleWorker.h](../src/abatcher/include/moduleWorker/moduleWorker.h)/[.cpp](../src/abatcher/src/moduleWorker/moduleWorker.cpp)) — подключается к USB (`connectToUSB`), инициализирует BSI устройства (`Device::CurrentDevice::initBSI`) и загружает XML-конфигурацию модуля (`loadXML`). По кнопке "Начать скачивание" (`startDownload`) сначала спрашивает путь для сохранения ZIP-архива (`FileFunc::chooseFileForSave`), затем последовательно скачивает и сохраняет во временную папку (`QTemporaryDir m_tempDir`): блок Bsi (`saveBsi`), блок BsiExt при наличии (`saveBsiExt`), конфигурацию (`requestConfig`/`saveConfig`) и журналы sys/work/meas (`saveJournals`/`saveJournal`), с прогресс-барами по каждому шагу и возможностью отмены (`cancelDownload`). По завершении конвейера (`finishDownload`) содержимое временной папки упаковывается в выбранный ZIP через `ZipUtil::CompressDir`, пользователю показывается итоговое сообщение. Кнопка "Назад" эмитит `finishWork()`, по которому `Abatcher` уничтожает `ModuleWorker` и возвращается к списку устройств.
- Реализованы шаги 1-6 и 17 (для того объёма файлов, что скачивается на шагах 1-6). Не реализовано: шаги 7-8 (Bac/Startup блоки), 9-16 (сравнение и обновление ВПО/конфигурации) — когда они появятся, их результаты тоже нужно будет складывать в `m_tempDir` до вызова `finishDownload`.
